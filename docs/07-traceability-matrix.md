## Вывод по пустым ячейкам

**Закрыто по итогам ревью.** До исправлений пустыми были: класс и тест для ФТ 6 (файлы), тест для ФТ 14 (роли), модуль и класс для ФТ 15 (журнал), тест на уведомление о сроке для ФТ 16 и класс для ФТ 17 (история). Их закрыли коммиты по замечаниям 3, 5 и 8.

**Что ещё нужно добавить:**

1. **Тест-кейсы для ФТ 3, 5, 9, 10, 11 и 13.** Нужны проверки фильтрации по приоритету, добавления комментария, удаления задачи (с подтверждением и записью в журнал), добавления задачи в проект, отображения дашборда и удаления учётной записи. Без них эти требования нельзя считать проверенными.
2. **Классы для ФТ 11 и 12.** Пустая ячейка здесь объяснима: дашборд и отчёт не хранятся, а каждый раз собираются модулем отчётности из данных Task. Это нужно записать в описании модуля отчётности. Если отчёты понадобится сохранять, нужен класс Report.
3. **Сценарии.** Два сценария покрывают только 7 из 18 требований и не затрагивают администратора вовсе. Нужно добавить хотя бы сценарии «Назначение роли пользователю» (ФТ 14–15) и «Формирование отчёта» (ФТ 12).
